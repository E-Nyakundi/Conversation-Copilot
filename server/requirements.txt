# Phase 1 — VAD + STT (required for AudioStreamConsumer)
#
# CPU-only torch, pinned explicitly (2026-08-14, after a prod deploy
# filled the VM's disk: the plain PyPI `torch` wheel bundles the full
# CUDA runtime — nvidia-cublas/cudnn/nccl/etc, several GB of libraries
# like libcublasLt.so — even though this VM has no Nvidia GPU (2 vCPU
# AMD EPYC, see build plan §6a). `--extra-index-url .../whl/cpu` below
# points pip at PyTorch's dedicated CPU-only wheel index instead, so
# `pip install torch` resolves to the `+cpu` build with none of the
# Nvidia packages pulled in at all. If a real Nvidia GPU is ever added,
# remove this index line and the `+cpu` suffixes to get the CUDA build
# back.
--extra-index-url https://download.pytorch.org/whl/cpu
torch==2.4.1+cpu
torchaudio==2.4.1+cpu
faster-whisper>=1.0,<2.0

# Phase 3 — local LLM, the fallback path when Groq is unreachable/rate-
# limited. Was disabled here due to network timeouts building the source
# wheel (llama-cpp-python compiles a C++ extension via CMake — slow, and
# easy to time out on a modest VM link). Fixed 2026-08-15 the same way
# torch's CUDA-bloat problem was fixed earlier: point pip at the
# project's own prebuilt-wheel index instead of building from source, so
# `pip install` just downloads a .whl with no compile step at all. If
# this VM ever gets a real GPU, there's a matching cu-suffixed index on
# the same site for that instead of the plain "cpu" one below.
--extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cpu
llama-cpp-python>=0.3,<0.4
